🎯 Exam Cheat Sheet - Core Principles

🏗️ Multi-Agent Architecture

  • Coordinator is the CENTRAL HUB for all communication
  • Subagents never talk directly to each other
  • Coordinator decides task decomposition & delegation
  • Synthesis agent merges results (not coordinator)
  • Preserve separation of responsibilities

✅ Error Handling Golden Rules

  • Handle errors at the LOWEST capable level
  • Return structured context (type, query, partial results)
  • Distinguish access failures from valid empty results
  • Escalate only what you can't resolve locally
  • Never silently skip or hide failures

⚠️ Data Conflicts & Gaps

  • ALWAYS annotate conflicts with source attribution
  • Include coverage annotations showing gaps
  • Don't pick sides — let coordinator reconcile
  • Complete your work, don't block on conflicts
  • Graceful degradation with transparency

🔧 Tool Design Principles

  • Clear, distinct descriptions = correct routing
  • Principle of least privilege for tool access
  • Replace general tools with specific ones
  • Programmatic preconditions > prompt instructions
  • Validate at interface level, not instruction level

🤖 Claude Code CLI

  • -p / --print for non-interactive CI
  • --output-format json + --json-schema for structured output
  • CLAUDE.md = always loaded (universal rules)
  • Skills = on-demand (workflow-specific)
  • .claude/rules/ = path-based conditional rules

📦 Batch API vs Synchronous

  • Batch: 50% savings, up to 24hr latency
  • Use Batch for: overnight jobs, weekly audits
  • Use Sync for: blocking PR checks, interactive
  • Batch CANNOT handle iterative tool calls
  • Match API to latency requirements

🚫 Common Wrong Answers

  • ❌ Silently skip errors or return empty success
  • ❌ Agents communicate directly (bypass coordinator)
  • ❌ Apply credibility heuristics to pick sources
  • ❌ Terminate entire workflow on single failure
  • ❌ Use prompt instructions for safety-critical logic

📝 Prompting Best Practices

  • Few-shot examples > verbose instructions
  • Explicit criteria > vague guidance
  • Target examples at ambiguous edge cases
  • Key findings at START (primacy effect)
  • Self-critique stage for quality assurance

🔄 Agent Loop Control

  • stop_reason: "tool_use" → continue loop
  • stop_reason: "end_turn" → stop loop
  • Bundle related tool calls in one turn
  • PostToolUse hooks for data normalization
  • Structured error context enables recovery

📐 Claude Code Organization

  • CLAUDE.md: universal, always-on rules
  • .claude/rules/: conditional, glob-pattern rules
  • .claude/commands/: project slash commands
  • ~/.claude/: personal (overrides project)
  • Skills: on-demand with context: fork option

🎯 Escalation Rules

  • Escalate: policy gaps (no rule exists)
  • Escalate: unresolvable after local retry
  • DON'T escalate: contradictory evidence (handle it)
  • DON'T escalate: multi-issue messages (decompose)
  • DON'T escalate: customer might change mind

🐛 Root Cause Analysis

  • Narrow decomposition → missing coverage
  • Tool name/desc overlap → misrouting
  • Keyword-sensitive prompts → behavior bias
  • General tools → scope creep
  • Lost-in-middle → restructure input order

🏗️ Multi-Agent Research System Architecture

A coordinator-subagent pattern where a central coordinator orchestrates specialized agents.

Architecture Components

Coordinator Central hub. Decomposes tasks, delegates, reconciles conflicts, routes results. Has broadest context.
Web-Search Agent Searches external sources. Returns structured results. Handles timeouts with partial results.
Document Analysis Agent Processes uploaded documents. Extracts key information. Should NOT do web searches.
Synthesis Agent Merges results from all agents into unified output. Annotates coverage gaps.
Critical Pattern: All communication flows THROUGH the coordinator. Subagents never communicate directly. This enables centralized visibility, uniform error handling, and controlled information flow.

Error Propagation Strategy

Tiered Error Handling:
1. Transient failures → handle locally (retry)
2. Recoverable failures → return partial results + context
3. Unrecoverable failures → escalate to coordinator with full context
4. NEVER silently skip or terminate entire workflow

Structured Output

Review Quality Patterns

Few-shot examples Most reliable for consistent output format when instructions alone produce variable results
Explicit criteria Replace vague "check accuracy" with "flag only when claimed behavior contradicts actual behavior"
Split large reviews Per-file passes for depth + integration pass for cross-file concerns

Trust Management

When false-positive rates erode trust: Temporarily disable noisy categories (style, documentation) while keeping high-precision ones (security, correctness). Fix prompts, then re-enable.

🎯 Exam Strategy

Answer Elimination Framework

Step 1: Identify what the question is REALLY asking — is it about root cause, best fix, or design pattern?
Step 2: Eliminate answers that violate core principles (direct agent communication, silent errors, etc.)
Step 3: Among remaining options, prefer the one that addresses ROOT CAUSE over symptoms

🧠 Mnemonic: "PACED" — Priority Order for Solutions

Programmatic enforcement > Architectural design > Clear descriptions > Examples > Documentation/instructions

When safety/reliability is at stake, prefer deterministic solutions (programmatic) over probabilistic ones (prompt instructions).

💡 Recurring Patterns in Questions

Pattern 1: "Most Effective Fix"

Almost always = fix the root cause at the source, not add layers/workarounds.
• Misrouting? → Fix tool descriptions/names
• Scope creep? → Replace with constrained tool
• Inconsistent output? → Few-shot examples
• Wrong sequencing? → Programmatic precondition

Pattern 2: "How to Handle Error"

Answer hierarchy:
1. Handle locally if possible (transient failures)
2. Return structured context to coordinator
3. Include: error type + what was tried + partial results + alternatives
4. NEVER: silent skip, full termination, or empty success

Pattern 3: "Which API/Approach for This Workflow"

Decision key:
• Blocking/interactive → Synchronous
• Scheduled/overnight/weekly → Batch (50% savings)
• Needs tool calls mid-request → Synchronous (batch can't)
• Cost optimization → Match each workflow individually

Pattern 4: "Configuration/Organization"

• Universal rules → CLAUDE.md
• Path-specific → .claude/rules/ with globs
• On-demand, might pollute context → Skills with context:fork
• Team shared → project .claude/
• Personal override → ~/.claude/ (same name wins)

🔄 Reusable Patterns

Pattern: Coordinator-Subagent Communication

Star Topology

All agents connect ONLY to the coordinator (hub). Benefits: centralized visibility, uniform error handling, controlled information flow.

Q2: Results go to coordinator → then to synthesis agent
Q8: Main advantage = observe all interactions, handle errors, control info flow
Q11: Coordinator partitions research space before delegating

Pattern: Graceful Degradation with Transparency

Complete + Annotate + Delegate

1. Complete what you can
2. Annotate what's missing/uncertain
3. Delegate decisions to whoever has broader context

Q1: Both values + conflict annotation → coordinator reconciles
Q5: Synthesis with coverage annotations showing gaps
Q12: Distinguish timeout (retry?) from empty (valid finding)

Pattern: Least Privilege / Constrained Tools

Make Wrong Things Impossible, Not Just Discouraged

Constrain at the interface level: replace general tools with specific ones, add programmatic preconditions, restrict tool access.

Q10: fetch_url → load_document (validates document URLs only)
Q15: Limited verify_fact tool vs full web-search access
Q39: allowed-tools in skill frontmatter
Q51: Precondition blocks lookup_order until get_customer succeeds

Pattern: Root Cause First

Fix the Source, Not the Symptoms

When something goes wrong, trace upstream. The fix should be at the point where the error originates.

Q4: Coordinator decomposition too narrow (not agent execution)
Q7: Tool name overlap causes misrouting (rename tool)
Q14: Agents output too much (fix output structure, not add summarizer)
Q56: Keyword-sensitive prompt creates behavior bias

Pattern: Context Isolation

Fork When Context Pollutes

Use context: fork when a skill produces verbose output or exploratory content that shouldn't influence the main conversation.

Q35: /analyze-codebase fills context → fork isolates
Q43: /explore-alternatives pollutes with rejected ideas → fork
Q45: Discovery phase fills window → subagent returns summary

Pattern: Structured Error Context

Tell the Coordinator EVERYTHING It Needs

Include: failure type, what was attempted, partial results obtained, and suggested alternative approaches.

Q3: Local recovery for transient + escalate unrecoverable with context
Q6: Return error with context to coordinator
Q9: Structured: failure type + query + partial results + alternatives

Pattern: Self-Critique / Evaluator-Optimizer

Review Before Presenting

Add a stage where the agent evaluates its own draft against concrete criteria before delivering to the user.

Q17: Independent reviewer without access to generator's reasoning
Q52: Self-critique for completeness (policy context, timeline, next steps)

Pattern: Information Architecture for LLMs

Primacy + Structure + Compression

Put key info at the start. Use explicit headings. Return structured data (not verbose prose) from upstream.

Q13: Key-findings summary at start + section headings (lost-in-middle)
Q14: Structured data (facts, quotes, scores) instead of raw content
Q54: Persistent "case facts" block outside summarized history
